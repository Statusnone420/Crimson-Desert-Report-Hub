# Approved decisions and gates

The replacement direction resolves the routine product choices below. The owner approved the layout and website identity. Implementation verification is recorded separately.

| Decision | Approved direction |
| --- | --- |
| Product shape | One desktop-only integrated dashboard with seven internal destinations. |
| Routes | Keep public/authenticated compatibility; do not promise a URL migration. |
| Claims | Exact current-patch durable pairing. Confirm/reject/later/history/undo; Lock is separate break-glass. |
| Claim scope | Keep current public-cluster mapping. Private-cluster expansion is not the default. |
| Later | One active count; operator-seen and scanner last-seen are separate. |
| Obsolete claims | New patch, corrected text, or removal retires active pairings but preserves history. |
| Scanner | Keep 2h / 3-search baseline. `dry_run` retains its private ledger while preventing public and pairing writes; preview protection remains separate. |
| Brief | One approved default brief with safe counts/next steps; no interview; stable keys remain. |
| Remaining workspaces | Videos and Dossiers are required parts of the overhaul. |
| Review | Preserve old review as historical; fresh review of the replacement prototype before production UI integration. |

Merge, hosted migrations, and deployment are not product-design decisions. They require explicit approval after implementation and verification evidence is available.
